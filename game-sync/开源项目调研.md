## 0. 三十秒结论

1. **帧同步先读「服务器怎么组帧」，再读「客户端怎么确定性重放」，最后才碰预测回滚。** 直接从 GGPO 入门会卡在「为什么需要回滚」上。
2. **状态同步的骨架只有四件事**：服务器权威模拟 → 快照/delta 编码 → 不可靠 UDP 传输 → 客户端预测 + 插值校正。按这个顺序找项目，不要从 skynet / ET 这种万行框架入门。
3. **教学性价比最高的两个入口**：帧同步看 `CraneInForest` 三件套（README 本身就是一篇中文帧同步长文）；状态同步看 `thatjoaoguy/unity-fastpacedmultiplayer`（74 个文件，把 Gabriel Gambetta 四篇文章逐一实现）。
4. **想学「工业界怎么排查不同步」**：只有三个活教材 —— OpenRA 的 `SyncReport.cs`、OpenTTD 的 `debugging_desyncs.md`、0 A.D. 的 `TurnManager.cpp`。

## 3. 两条技术栈路线图

```
帧同步（Lockstep）                              状态同步（State Sync）
─────────────────────                          ─────────────────────
输入采集 + 帧对齐                               传输层
  CraneInForest / Lockstep-Tutorial              GameNetworkingSockets / LiteNetLib / yojimbo
        │                                              │
        ▼                                              ▼
帧服务器（只组帧，不算逻辑）                      权威模拟（服务器 tick）
  byebyebruce/lockstepserver                     colyseus Room / nakama match / ET
        │                                              │
        ▼                                              ▼
确定性仿真（难点：不能有浮点）                    快照 + delta + 位打包 + 量化
  Lockstep.Math / FixedMathSharp                 colyseus/schema / PurrNet BitPacker / bevy_replicon
  Kimbatt 确定性物理                                    │
        │                                              ▼
        ▼                                        客户端预测 + 校正
帧校验和 / desync 排查                             unity-fastpacedmultiplayer / chickynoid
  OpenRA SyncReport / OpenTTD debugging_desyncs         │
        │                                              ▼
        ▼                                        插值 / 外推 / 延迟补偿
回滚（实时化变体）                                 snapshot-interpolation / godot-state-sync-demo
  GGPO / GekkoNet / backroll-rs
```

**读的时候注意分工**：左列的项目几乎都同时包含「帧同步 + 回滚」两级（因为实时格斗/竞技必须回滚），右列的项目几乎都包含「权威 + 预测 + 插值」三层。**不要指望一个项目同时教会你两条路线**——`wqaetly/NKGMobaBasedOnET` 是罕见的混合案例，正好用来做对照。

## 5. 选型速答（给要动手的人）

- **要做 MOBA / RTS / 塔防 / 卡牌对战回放**：帧同步（锁步）。参考 `CraneInForest`（模型）、`lockstepserver`（服务器）、`GGPO`（若需要实时手感）。
- **要做 FPS / 动作 / 载具驾驶**：状态同步（权威 + 预测 + 延迟补偿）。参考 `GameNetworkingSockets`（传输）、`chickynoid`（角色控制器）、`unity-fastpacedmultiplayer`（预测校正闭环）。
- **要做 MMO / 开放世界**：状态同步 + AOI + 分片。参考 `skynet` / `nakama` / `ET`。
- **要做派对 / 休闲 / 卡牌回合**：状态同步，甚至不用预测。参考 `colyseus`（schema delta 足够）。
- **要做格斗 / 平台跳跃**：回滚网络（GGPO 系）。参考 `GGPO`、`GekkoNet`、`backroll-rs`。
- **混合**：战斗用帧同步 + 大厅/背包/掉落用状态同步，是业界最常见组合；接口设计见手册第 11 章。

## 7. 与同类材料的差异（诚实复盘）

上一轮做 TCP/UDP 学习包时，最大的流程疏漏是**开工前没有调研 GitHub 同类项目**（已写在 [../参考项目调研与改进清单.md](../参考项目调研与改进清单.md)）。这次把调研前置为一等公民任务，并做了三件上一轮没做的事：

1. **元数据全部走 API/代理取真值**，禁止凭记忆写 ★ 数与许可证；取不到就写「未核实」。
2. **给出「读哪几行」而不是只给链接**——每个条目都指向具体文件/目录，且标注来源是 README 还是目录核对。
3. **明确写「哪些跑不起来」**：老 Unity 工程、依赖私有仓库的项目、已归档镜像，都逐个标了坑，避免你花两小时配环境最后放弃。
