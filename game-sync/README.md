# 帧同步与状态同步学习包

一套「能读、能点、能跑、能查」的游戏网络同步学习材料。纯本地、零依赖、可离线。

沿用上一个学习包（[TCP/UDP](../README.md)）的三件套结构：**手册讲原理 → 实验室建直觉 → 脚本做真实验**，额外加了一份**可核查的开源项目调研**（上一轮的流程疏漏，这次前置成一等公民任务）。

## 一、先说清楚这两个词

| | 帧同步（Lockstep / 确定性） | 状态同步（State Sync / 服务器权威） |
|---|---|---|
| 同步的是什么 | **输入指令**（谁在第 N 帧按了什么） | **结果状态**（服务器算完的世界长什么样） |
| 谁跑逻辑 | 每个客户端各跑一份**完全相同**的逻辑 | 只有服务器跑权威逻辑 |
| 成败关键 | **确定性**：浮点、随机数、遍历顺序任一不干净就分叉 | **带宽与延迟**：发什么、发多少、怎么预测 |
| 典型游戏 | RTS、MOBA、塔防、格斗（回滚）、卡牌对战回放 | FPS、MMO、开放世界、载具、派对游戏 |
| 一句话代价 | 宁可「卡」不可「错」——一个人慢，全房间等 | 宁可「糊」不可「算错」——用预测和插值掩盖延迟 |

想看详细对比：手册第 11 章有 12 维对比矩阵 + 决策树；实验室第①个模块有两条同轴时间线并排演示。

## 三、快速开始

### 1. 打开实验室（1 分钟）

双击 [`lockstep-lab.html`](lockstep-lab.html)，左侧按 ①→⑧ 顺序点一遍。**建议先看第③个模块（确定性实验）**：它会同时跑「float 三端」和「定点三端」，你能亲眼看到 float 版从第 32 帧开始哈希不一致、而定点版 900 帧零分歧 —— 这是理解「为什么帧同步怕浮点」最快的方式。

### 2. 跑真实 UDP 演示（5 分钟）

```powershell
cd E:\DeepSeekHarmess\学习\game-sync\code

# 锁步：帧服务器 + 3 客户端进程，真实 UDP
python lockstep_demo.py demo       # 200 帧三端校验和逐帧一致
python lockstep_demo.py desync     # 反例：float 分歧从 1e-17 放大到 4.83，定点零偏差
python lockstep_demo.py jitter     # 30% 丢包 + 50-150ms 抖动，冗余帧 A/B 对照
python lockstep_demo.py catchup    # 客户端落后 60 帧后快进追帧
python lockstep_demo.py replay     # 900 字节输入回放 300 帧，改 1 bit 就偏离
python lockstep_demo.py bandwidth  # 锁步 vs 状态同步带宽对比
python lockstep_demo.py all        # 以上全部

# 状态同步：服务器权威 + 快照广播
python statesync_demo.py snapshot  # float64 33B → int16 9B，误差 0.0076
python statesync_demo.py delta     # 全量 142B → 增量 89B，116 帧无损重建
python statesync_demo.py predict   # RTT 150ms：操作延迟 184ms → 17ms
python statesync_demo.py interp    # 插值缓冲：重复帧 117 → 4
python statesync_demo.py bandwidth # 不同实体数/tick 率的带宽
python statesync_demo.py all       # 以上全部
```

> Windows 上如果 Python 输出中文乱码，先执行 `chcp 65001` 或设 `$env:PYTHONUTF8='1'`。

- 想去看源码：[`开源项目调研.md`](开源项目调研.md) 第 4 节有一张按周排的阅读表，每个阶段都有自检标准。

## 五、环境要求

- **浏览器**：任意现代浏览器（实验室零外部依赖，离线可用）。
